# Contributing

Thank you for helping. Small, focused pull requests are easiest to review.

1. Open an issue first for anything larger than a fix or a new market or panel,
   so we can agree on the shape.
2. Keep the skill readable as a prompt: plain, precise English, no hype, no
   emoji. Instructions should say what to do and why.
3. Never add real people's profiles, quotes or personal data to examples or
   tests. Use fictional personas and placeholder domains such as example.com.
4. Run the tests before opening a pull request:

   ```bash
   python -m unittest discover -s tests -v
   ```

5. Add a line to `CHANGELOG.md` under "Unreleased".
